# Urban Folding / Beijing Route Atlas

北京 50 个功能节点的多方式出行交互地图，包含步行、骑行、驾车、公共交通四种规划方案，以及路径长度和预计耗时对比。

## 打开地图

下载本仓库后，用新版 Chrome、Edge 或 Safari 打开 [beijing_route_atlas.html](beijing_route_atlas.html)。无需启动服务器、配置 API Key 或安装 Python。GitHub 的文件页面展示源码，不直接运行该网页；本仓库不默认启用 GitHub Pages。

网页内嵌 50 个节点、9,763 条有效路线的展示数据及道路背景。地图数据可离线使用；Google Fonts 外链需联网，离线时使用本地备用字体。浏览器需要支持 `DecompressionStream`。

- 选择、互换起终点；点击地图节点设置终点，Shift + 点击设置起点。
- 切换当前点对、单起点全部目的地、全网络范围。
- 开关四种交通方式，按最大耗时过滤，导出筛选结果 CSV。
- 路径长度（km）和预计通勤时间（min）联动对比；多点范围展示各方式可用样本的中位数及样本量，不是严格匹配点对的统计比较。
- 地图拖动、缩放、适配视图；密集网络使用缓存，放大后恢复矢量绘制。

## 数据口径

| 项目 | 内容 |
| --- | --- |
| 节点 | 50 个目的性采样节点，覆盖北京 10 个行政区 |
| 功能分组 | 就业商务、交通枢纽、教育医疗、商业文化、居住片区代表设施；各 10 个 |
| 查询范围 | 50 × 49 个有向点对 × 4 种方式 = 9,800 条记录，不查询自己到自己 |
| 路线采集时间 | 北京时间 2026-11-02 21:02–22:05 |
| 有效路线 | 步行 2,414；骑行 2,450；驾车 2,450；公共交通 2,449 |
| 缺失 | 36 条步行超出 API 规划范围，1 条公共交通传输错误；均不代表已确认现实不可达 |
| 数据来源 | 高德 v5 路径规划接口；选择返回候选中最短正耗时方案，不保证全局最优 |
| 坐标系 | GCJ-02；不是标准 WGS84 GeoJSON 语义 |

这些是历史查询时的规划路径和预计耗时，**不是实时交通数据、同步出发快照或实测 GPS 轨迹**。网页不会自动更新。公共交通包含公交/轨道及步行接驳，页面使用接口返回的方案总耗时，不自行补加候车时间；候车时间的具体计算口径未独立核验。失败请求不会用步行替代。

节点未核验出入口；居住片区代表设施不是住宅或居民家庭起点。该样本不具备人口代表性，不能将全样本中位数解释为北京居民典型通勤水平。展示路线经过简化；OSM 道路背景近似转换至 GCJ-02，可能有偏移。公交几何缺口不连接，地铁可能为站间示意。

## 项目结构

- `beijing_route_atlas.html`：当前可直接打开的独立网页。
- `main.py`：构建入口，仅依赖 Python 3 标准库。
- `src/`：页面模板、FrontierCS 风格样式、图表及地图绘制模块。
- `swiss_routes.html`：历史页面，也是当前构建所依赖的压缩路线和道路数据容器，**请勿删除**。
- `beijing_functional_50/`：节点清单、选点查询及复核资料。
- `beijing_functional_50_routes/`：当前路线批次的节点、时间距离长表、统计与采集说明。
- `select_beijing_nodes.py`、`collect_50_routes.py`：历史采集脚本，仅供审查及按需适配。

## 本地构建

```bash
python3 main.py
```

构建从 `swiss_routes.html` 提取压缩展示数据，并将 `src/` 的样式和脚本内联到 `beijing_route_atlas.html`。不调用外部采集接口，不需要大体积原始数据。修改前端后重新构建并刷新浏览器即可。

## 大文件不随 Git 分发

以下文件仅保留在原始本地工作区，已被忽略：

- `beijing_functional_50_routes/responses.jsonl`：完整原始 API 响应，约 329 MiB。
- `beijing_functional_50_routes/route_geometries.json`：未简化的选中路线几何，约 136 MiB。
- `beijing-260101-free.shp.zip`：原始 GIS 数据，约 66 MiB。

缺少这些文件不影响现有地图使用或前端重建，但不能据此仓库完整复核原始响应或分析未简化几何。内嵌展示数据不是原始数据的无损替代。

## 采集注意事项

浏览和构建不需要密钥。采集脚本通过 `AMAP_KEY` 环境变量读取密钥，使用前自行安装 `requests`；旧的建筑选点分支另依赖 `pyshp`、`shapely`。不要提交真实密钥或 `.env`。

不要直接对现有目录重新运行选点脚本：最终节点经历人工纠正，而脚本只保留初选流程。路线脚本按已有请求记录跳过，不自动重试失败记录；未经适配和复核不要用于覆盖当前批次。脚本部分头注释和准备分支仍来自早期试点，实际路线查询上限为 9,800。
